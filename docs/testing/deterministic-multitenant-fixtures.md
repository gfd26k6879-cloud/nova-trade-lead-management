# Deterministic multitenant fixtures

The browser-safe canonical fixture catalog uses fixed synthetic IDs only. It creates two tenants, two active workspaces per tenant, every launch role, and pending, suspended, and disabled membership cases. The catalog also exposes exactly two tenant-owned workspace look-alike record IDs for unit, integration, and E2E selectors. Setup is transactional; callers can use the rollback wrapper so callback rows are removed too, or call the explicit committed cleanup helper. Cleanup deletes only canonical child and parent IDs in foreign-key-safe order, is idempotent, and cannot remove unrelated rows.

`tenant-fixtures-postgres.test.ts` is opt-in. Set `Q002_POSTGRES16=1` and `Q002_POSTGRES_ADMIN_URL` to a loopback PostgreSQL 16 administrative URL. The test refuses non-loopback targets, creates a uniquely named disposable database, installs only the schema required by the fixture repository statements, runs committed setup/cleanup twice, proves unrelated-row preservation and rollback cleanup, then force-drops the disposable database.
